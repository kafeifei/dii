# 烬渊 Ember Abyss

这个项目在探索：用 AI 把《暗黑破坏神 2》做出来，路径是什么样的。

**在线试玩：<https://dii-abyss.vercel.app>**（用桌面浏览器打开，存档保存在浏览器本地）

它是一款在浏览器里跑的单机 ARPG，玩法向暗黑 2 看齐，用 TypeScript + Three.js 写成，固定斜俯视正交相机。代码、美术、数值和测试都由 AI 完成，人负责定方向、拍板规则和试玩验收。美术是按同一套风格版 AI 生成的暗黑哥特半写实 3D 资源：角色、怪物、道具、建筑、武器装备、地面和墙面贴图（见下方「AI 美术」，来源见 `public/models/CREDITS.md`）；背包里的物品图是在我们自己的 GPU 机器上用开源模型画的（见「物品图」，来源见 `public/icons/CREDITS.md`），特效、技能和任务图标是代码实时生成的。音效、环境声和主角的中文配音由 ElevenLabs 生成，营地、野外和洞穴的音乐由 ACE-Step 1.5 在我们自己的 GPU 机器上生成（见「AI 声音」，来源见 `public/audio/CREDITS.md`）；还没有录音的声音由代码合成，音乐录音放不了时由代码现场作曲。模型加载失败时会自动退回程序化角色和道具，录音加载失败时退回合成音。

## AI 实现路径

把暗黑 2 拆成代码、美术、数值、验证四条线，每条线都找一种 AI 能稳定产出、又能自己检查结果的做法。

**代码：AI 直接写，规则和画面分开。** 全部 TypeScript（约 1.8 万行）由 Claude Code 编写。游戏规则放在 `src/game/`，不依赖渲染，同一套逻辑既能在浏览器里玩，也能被机器人快进着跑。

**美术：程序化占位 → 免费模型包 → 统一画风的 AI 生成。**

1. 原型阶段，角色和道具全用代码拼，先把玩法跑通。
2. 换成 CC0 模型包（KayKit、Quaternius），把模型加载、动画和摆放这条管线打通。
3. 定一张风格版，让图像模型照着它画设定图，再用 Meshy 转成带贴图的 3D 模型、自动绑骨、套用动作库。导入、对齐、截取动作、减面这些由工具链完成（见「AI 美术」）。

每一步都沿用同名的模型键，后一步替换前一步时，摆放模型的代码不用改。

**数值和规则：用原版数据，不靠模型的记忆。** 物品（全部底材、魔法和稀有词缀、暗金、套装、符文、宝石、符文之语、赫拉迪克方块配方）、职业和难度表、经验表、商人的货架和价格、掉落表都从《暗黑破坏神 2：重制版》的数据表导入（`tools/d2-import.mjs`；专有名词换成项目自己起的名字，见 `tools/d2-names`，通用的叫法用官方简中）。公式照逆向重写的原版逻辑 [D2MOO](https://github.com/ThePhrozenKeep/D2MOO) 实现，每条规则在代码注释里标明出处。AI 负责把这些表接到游戏机制上。

**验证：让 AI 自己看得见、量得出。**

- 画面：用无头浏览器截图（`tools/play.mjs`、`tools/sheet.mjs`），改完对比前后的图。
- 平衡：机器人按区域一路打下去，16 轮并行，按区域统计死亡中位数和死因（`tools/balance.mjs`）。调数值看数据，不靠感觉。
- 性能：在真 GPU 上按区域逐场景测每帧耗时，再让主角沿路线走一段，看帧时间的中位数、p95、p99 和内存变化（`tools/bench.mjs`）。
- 手感和观感最后还是靠人试玩。比如走路时主角抖动，就是试玩时发现、再写脚本量出原因修掉的。

### 目前的体会

- 先对齐再动手。平台、玩法支柱、画风这些大方向先定下来，AI 才不会做偏。
- 能拿到原始数据的规则，就不让 AI 凭记忆写数值和名字。
- AI 生成的 3D 资源不能直接用，要靠工具链和代码补齐：Meshy 的骨骼没有手指，动作里手腕会乱晃，非人形的怪绑不了骨。对应的办法是从手部网格量出握点、截取出手的那一段动作、用顶点着色器做动作。
- 验证必须自动化。AI 能自己截图、跑机器人、跑基准，才能自己发现问题、证明修好了。
- 多个 AI 会话可以并行做不同的线（美术、物品、渲染），用分支和小提交隔开。

### 还没走通的

- 第一幕的大地图目前只有营地、血沼荒原、凛寒原野和邪秽巢穴；凛寒原野的地面是血沼荒原的贴图调冷调淡，还没有自己的贴图；邪秽巢穴和试炼场还没有录制的环境声，放的是合成的低鸣；地面上还没有立体的草丛和灌木，只靠贴图。
- 蝙蝠、幼龙这类非人形怪还没有绑骨，只能用顶点着色器做简单动作。蜘蛛已经换成 Tripo 绑好骨的模型，但它只带走路，咬和死是代码摆的。
- 动作库是给空手做的，持武器的动作和技能专属动作还不够。
- 技能和任务图标还是代码画的。第一个月的声音已经生成：约 50 条核心音效（挥砍、命中、格挡、死亡、按种类区分的掉落、暗金和符文掉落、拾取、喝药、界面、升级、传送门、传送点、宝箱、木桶、神龛）、营地和野外的昼夜环境声、两位主角各 30 句中文提示语；技能音效和怪物叫声仍是代码合成。主角的台词已经接到游戏里现有的时机上（见「AI 声音」），找到邪秽巢穴和完成任务时也会说；区域清空、怪群来袭这些还没有对应事件的台词先不说。ElevenLabs 免费档不开放音乐接口，音乐改用开源的 ACE-Step 1.5 生成，营地、野外、洞穴各有一首（营地两首轮流放）；现在用的是 turbo 模型的版本，4B 的 XL-sft 模型正在出更好的版本，挑好了再换。
- 内容量：目前只有两个职业；怪物只做了第一幕开头这几个区域的（见「已实现」），后面区域的怪物等区域做好再加；任务只有第一幕的第一个（涤荡邪巢），NPC 只有亚喀蕾一个人说话，台词还没配音。
- 画面上限：浏览器里的 WebGL 做不了体积光和全局光照。要更好的画面，可能得换桌面引擎（比如 Godot）。

## 运行

```bash
npm install
npm run dev
```

打开终端里打印的地址即可（默认 http://localhost:5174/）。

存档在浏览器本地（localStorage），最多 8 个角色，标题页左边列出已有角色（可继续或删除），右边选职业建新角色；每隔几秒、换层、关页面时自动保存，游戏中刷新会直接回到刚才那一层。存档跟地址绑定，换了端口就看不到原来的存档，所以开发服务器固定用 5174 端口。存档要升级格式之前，会先把原样备份到 `dii-save-v1-backup-<存档位>-<版本>`（v4 以前旧存档的备份和每个角色第一次升级前的那份一直保留，其余的每个存档位只留最近一次升级前的一份；删除角色时备份不删）；更新版本写的存档照样能玩，但只读、不回写；这个版本认不出的物品不会删掉，变成「未知物品」放在储物箱旁边，换回认得它的版本就会恢复。

发布到 Vercel（团队 kafeifeis-projects 下的 dii 项目，本目录已经关联）。在没有未提交改动的检出上运行：

```bash
vercel build --prod
vercel deploy --prebuilt --prod
```

地址后加 `?dev` 是测试模式：跳过标题页直接开一个测试角色，用单独的存档位，不会覆盖正式存档；页面不可见时也继续跑模拟（方便自动化测试）。默认开圣殿骑士，`?dev&sorc` 开法师；`?knight` 让圣殿骑士换回原来的 KayKit 骑士模型。`?dev&lvl=3` 直接从试炼场第 3 层开始；`?dev&tod=0.5` 把营地和野外的时间定在一天中的某个时刻（0 午夜、0.25 黎明、0.5 正午、0.75 黄昏），方便截图。`?dev&gallery` 把营地换成展示间：每个道具、营地物件、怪物和每种底材的掉落外观各摆一个，用来审美术。

调试面板：按 `` ` `` 键或在暂停菜单点「调试」打开，可以给当前角色加等级和金币、在脚下掉随机装备（也可以指定魔法、稀有、套装、暗金）和符文宝石、指定这些掉落的物品等级、一键鉴定背包、储物箱和身上的全部物品、开无敌、把经验和怪物掉落翻 2 到 100 倍、直接去任一区域（营地、血沼荒原、邪秽巢穴、凛寒原野）或下一个区域、进试炼场（无尽地下城的任一层，每次进都重新生成，可以同时选难度，用来试高等级的怪物和掉落）、选难度。正常游戏里已经没有无尽地下城，只能从这里进。难度会记进存档：传送点按难度分开记，怪物、宝箱和木桶按这个难度的掉落表掉东西，宝箱和木桶的物品等级是这个难度的区域等级（比如噩梦的血沼荒原是 36 级），抗性扣这个难度的惩罚（噩梦 −40、地狱 −100），噩梦和地狱死亡时还要扣经验。怪物也换成这个难度的：属性用怪物表里这个难度的那一列，噩梦和地狱里的等级照原版取区域等级（首领等少数例外），掉落的物品等级就是怪物等级。它改的是正式角色，会存进存档；倍率、物品等级和无敌按浏览器记住，不进存档。本地开发服务器上一直有这个面板；打包后的线上版要先用 `?debug` 打开一次才出现，`?debug=0` 再关掉。

**手机和平板**（横屏，竖着拿会提示横过来），操作照《暗黑破坏神：不朽》的路子：

- 左半屏按住拖动是摇杆，用来走路；在那里轻点一下等于点地面。
- 右下角的圆按钮是攻击和技能。点按或按住，打脚下有圈的敌人（圈变红表示正在打它）；点一下怪物可以锁定它。
- 法术按钮按住拖动是手动瞄准：飞弹显示一条线，暴风雪、陨石这类落在地上的显示一个圈，拖得越远落得越远；松手施放，拖回按钮上松手取消。
- 靠近物品、宝箱、商人、传送点时，技能按钮上方出现交互按钮，点它拾取或使用。
- 换技能：打开「技」，点一个技能，再点右边的技能键；直接点技能键可以从列表里挑（包括普通攻击）。
- 背包和商店里：点一下看说明，再点一下拿起（商店里的东西是商人先问买不买），长按相当于右键（使用、装备、直接购买；卷轴和药剂长按会照 Shift+右键补满）。
- 安卓可以点左上角的 ⛶ 全屏。iPhone 的 Safari 不支持网页全屏，要从分享菜单「添加到主屏幕」，再从主屏幕打开。
- 在电脑上加 `?touch` 也能看到手机版的界面。

暂停菜单（Esc）和标题页都有「设置」：画质预设（低 / 中 / 高）、渲染分辨率、抗锯齿、动态光照、阴影、画面特效、粒子特效、帧率显示、音量、静音和屏幕震动，改了立刻生效（抗锯齿会重新载入页面），存在浏览器本地，不跟存档走。

背包里：右键使用药剂或直接装备；右键鉴定卷轴或鉴定之书，再点一件未鉴定的物品就鉴定它；右键城镇传送卷轴或城镇传送之书打开回城门，传送门打开时才用掉一张卷轴或书里的一次（施法被打断不算）。书照原版最多装 20 张：把同种卷轴拿起来点到书上就补一张，买的、捡的卷轴背包里有没满的书就直接放进去，捡到另一本同种的书会把里面的卷轴并进背包里那本。新角色照原版职业表开局：武器（和盾）、腰带里 4 瓶初级治疗药剂、背包里一张城镇传送卷轴和一张鉴定卷轴；以前回城不要卷轴，旧存档的角色背包里没有回城卷轴或书的，读档时送一本 5 次的城镇传送之书，只送一次。Ctrl+左键（Mac 上 ⌘ 也行）照 D2R：开着储物箱（显示的那一页）或魔盒时在它和背包之间存取，在商店里直接出售，都没开时丢在脚下；何罗德门魔盒和这个版本认不出的物品不会丢，拿在鼠标上点地面也一样；按住 Ctrl 点右键仍是右键。Shift+左键照原版把背包里的药剂放进腰带，卷轴只放到腰带里已有同种卷轴的那一列（先手动放一张上去），腰带放不下就什么也不做；捡起和买来的药剂会自己进腰带，卷轴照原版的本意不会，只能 Shift+左键或手动放；这样放进去的只跟同类放一列（治疗药剂或法力药剂大小可以混放），治疗、法力和复苏药剂没有同类的列时占一个空列；拿在鼠标上点到腰带上则照原版什么都能放进点的那一列，药剂卷轴混放也行，只要那一列还有空位；腰带里的卷轴也能右键或按数字键使用，回城卷轴按 P 也会用到；把符文、宝石或珠宝拿起来点到有孔装备上就是镶嵌，镶进去就取不出来，符文顺序对上就会变成符文之语。拿着物品点背包或储物箱里的何罗德门魔盒，不用打开就能放进去。

营地里跟商人亚喀蕾说话，生命和法力回满，中毒、冰冻减速和流血也会解除，然后弹出她的菜单：「交谈」「交易／修理」「取消」。她一个人先兼着原版第一幕两个商人的货架：铁匠的武器和防具，药剂师的法杖、药剂、卷轴和书；货架按角色等级 +5 进货（普通难度第一幕最高 12 级），每次回营地重新进货，买卖价格照原版的公式和倍率。商店里点「修理」再点一件物品修它，或者「全部修理」修好身上的。买东西和修理都先用身上的金币，不够的从储物箱里扣，只扣自己那一页的金币，共享页的不算（D2R 的商人只看得到个人储物箱）。买卖照原版的点法：货架上的东西右键直接买，左键点商人先问一句买不买（Enter 确定，Esc 取消）；拿着物品点到货架上，商人问一句卖不卖，Ctrl+左键点背包里的东西直接卖掉。背包里有没满的书时，买的同种卷轴直接放进书里，Shift+右键（手机上长按）按卷轴的价格一张张把书补满，金币只够几张就补几张；Shift+右键买药剂会一瓶瓶把腰带装满，买钥匙、箭、弩矢会把身上或背包里那一组补满，没有就买满满一组。只有商人常备的货能这样连买；噩梦和地狱里的高级、超级治疗和法力药剂也算常备（原版如此）。

## 已实现

- **职业**：开局在标题页选择，每个职业三系 15 个技能，有前置技能和协同加成
  - 圣殿骑士：战斗技能 / 进攻光环 / 防御光环，光环同时只能开一个
  - 两个职业和营地 NPC 的模型都是 AI 生成的（见下方「AI 美术」）
  - 法师：火焰 / 闪电 / 冰冷法术（火焰弹、火球、火墙、陨石、电荷弹、静电力场、新星、传送、连锁闪电、冰弹、冰霜新星、冰尖柱、暴风雪等），温暖是被动技能；拿双手法杖，生命少、法力多
- **世界**：照暗黑 2 第一幕的西块做成一张连续的大地图：放逐者营寨（酒馆、铁匠铺、民居、水井、墓园和几个 NPC，商人、储物箱、传送点）嵌在血沼荒原边上，再往外是凛寒原野，走出营地不换场景。血沼荒原里的邪秽巢穴是单独的一个洞穴场景，里面有超级暗金怪尸焰和他的朽尸随从。凛寒原野通往列石荒野和葬骨荒冢的路暂时封着。每局（新开或从标题页继续）都重新生成整张图，从营地出发，传送点保留；刷新页面接着玩同一张图
- **任务**：照暗黑 2 的任务记录，每个难度给每个任务记一组标志（已领奖、待领奖、已接、出过营地、到过任务区域、本局达成……），存在存档里，三个难度互不相干。第一幕六个任务都在任务日志（L，或底栏的「任」）里，目前只有「涤荡邪巢」能做：第一次跟亚喀蕾说话她就交代任务（头上有黄色「!」，小地图上也有），台词在屏幕上方的框里往上滚，可以跳过；没接任务直接走进邪秽巢穴也算开始；巢穴里只剩 5 只以下时每杀一只都报数，杀光就完成（提示、音效、日志更新，巢穴亮起来）；回去找她领 1 个技能点，当时没领的下一局也能领，只给一次。带任务掉落的怪（第一幕最后的昂妲蕾那种）按这个记录决定掉不掉任务掉落
- **野外**：按暗黑 2 的做法，区域按原版顺序摆在一张粗网格上，每个区域由 8×8 格的单元拼成：边缘是密林，出入口留开口，单元里放传送点、洞口、神殿和景点（墓园、废墟、怪物营地、石堆），一条主路连起出入口和传送点。地面按格子混合草地、落叶、土路和石板四种贴图，交界用噪声打散。营地和凛寒原野有传送点，用过才激活，按难度分开记；同一张图里用传送点、回城门、死后复活都是原地跳过去，不重新加载
- **区域交界**：每个区域有自己的样子：营地是踩实的泥地、高栅栏、暖色的光；血沼荒原是落叶和土、矮废墟、偏褐的暗部；凛寒原野的草地发白、雾更浓、光偏冷，风里飘着霜。地面在交界处几格之内碎块状地过渡，雾、调色和飘尘按主角离交界的远近逐渐变过去，昼夜照常。走进新区域时屏幕上方显示「进入 区域名」并淡出，在交界上来回走不会反复显示；小地图下方是当前区域名。每个区域按原版的声音环境（levels 表的 SoundEnv）放音乐和环境声：营地和野外不同，血沼荒原和凛寒原野相同；走过交界时交叉淡入淡出，在交界上来回走时两秒内最多切换一次，不跟着每一步来回切
- **昼夜**：营地和野外有昼夜循环，一天 16 分钟（游戏开始是早上）：太阳从画面左边升起，正午在左前方，傍晚落到右边，影子跟着转；夜里是月光，暗处只看得见主角身边一圈。地牢不受影响
- **神殿**：碰一下获得 96 秒增益（护甲、战斗、经验、技能、法力回复、抗性），同一时间只保留一个，剩余时间显示在小地图下方；回复神殿直接回满生命和法力
- **房间布景**：地牢房间按主题随机成为骨堂、小教堂、储藏室、大厅、书库、营房、墓室、白骨坑、乱石洞、废弃营地或柱廊，家具会挡路（生成时保证全图连通），烛台和灯笼会发光，墙上挂旗帜、书架和兵器
- **怪物**：照暗黑 2 的怪物表（MonStats、MonLvl）：等级、生命、防御、命中、伤害和经验都按原版换算。每个区域照关卡表从它的怪物列表里每局挑几种，按原版的密度成群刷出，再按原版的规则出冠军怪群、带原版词缀的暗金怪和随从（`src/game/d2/population.ts`）。普通难度第一幕开头：血沼荒原有朽尸、沉沦鬼、针鬃鼠；凛寒原野从巨躯魈、晦影女猎、晦影矛女、沉沦鬼巫祝（带着沉沦鬼）四种里每局挑三种，还有超级暗金怪必希鲍什和他的沉沦鬼；邪秽巢穴有朽尸、巨躯魈、沉沦鬼巫祝，和超级暗金怪尸焰带的 5 只朽尸。AI 照 D2MOO 的 MonAI 移植（`src/game/d2/monai.ts`）：沉沦鬼同伴死了会四散逃开，主角逼上来再回头打；沉沦鬼巫祝放火焰弹，还会复活倒下的沉沦鬼（复活的不再给经验、不掉东西）；针鬃鼠射刺、边射边退；晦影矛女比晦影女猎够得远；一群怪会一起发现主角。怪物按自己的掉落表掉东西。针鬃鼠和晦影女猎、晦影矛女的模型是这一版新做的。试炼场里是原版其他区域的怪物和首领（炉匠、绯鸦、昂妲蕾等）
- **装备**：暗黑 2 的物品系统，全部来自《暗黑破坏神 2：重制版》的数据表（以「术士之王」之前的内容为准）。底材是全部武器、防具和杂项（普通 / 扩展 / 精华，加护符、戒指、神符、珠宝、钥匙、卷轴和书）；弓、弩、标枪、投掷武器和其他职业的专属物品照原版掉落，能卖、能镶嵌，主角用不了就显示「不能使用」。品质照原版次序判定（暗金 → 套装 → 稀有 → 魔法 → 优质 / 普通 / 劣质），魔法装备几率（MF）带原版的递减；魔法和稀有物品用原版词缀，套装有每件的加成和整套的加成，还有符文之语和赫拉迪克方块配方。物品掉下来是未鉴定的，有耐久（打中时武器掉、被打时防具掉，到 0 就失效，要修理），少数会是无形的；神符放在背包里就生效。物品说明照原版的属性描述表写。怪物、宝箱和木桶按原版的掉落表掉东西：怪物按它的等级，宝箱和木桶按所在区域的等级（`src/items/d2/treasure.ts`）。旧存档里项目自己编的底材、暗金和套装都换到对应的原版底材上，保留原来的防御、属性和需求
- **关卡保留**：一局里大地图和邪秽巢穴都保持原样，打死的怪不会复活，离开再回来时活着的怪回满血并回到原位；试炼场每次从调试面板进都重新生成，死亡或用传送点回到刚离开的那一层时保持原样
- **系统**：格子背包、纸娃娃装备栏、腰带、商店买卖与修理、鉴定、储物箱、传送点、回城门、多角色本地存档。人物属性照原版的职业表和公式（`src/game/d2/`）：初始属性和每级、每点属性加的生命、法力、耐力，职业的药水效果，命中率和格挡率（跑动时格挡只有三分之一），抗性随难度扣惩罚，跑步耗耐力；杀怪经验按等级差打折扣；攻击、施法、受击硬直和格挡的时长照原版的速度档位，按职业、武器类别和攻速、施法速度、受击恢复、格挡速度算出帧数（每秒 25 帧，`src/game/d2/frames.ts`），动作按这个时长播放；死亡时按原版扣金币（背包加储物箱的 min(等级, 20)%），留下穿着全部装备的尸体，走回去点它就把装备拿回来；冰冻减速、中毒、偷取生命、致命一击
- **表现**：光照半径与动态火把、主角光源投影（营地和野外是日光或月光投影）、泛光与按场景或区域调色、贴地雾气与飘尘（墓穴的灰尘、冰窖的霜、地狱的余烬和发光熔岩缝、营地和野外夜里的萤火虫、白天的飞絮、凛寒原野的霜）、可穿透的遮挡墙、打击停顿、屏幕震动、血迹、碎骨与冰冻碎裂死亡、粒子特效、小地图与全屏地图、WebAudio 音效与环境音（ElevenLabs 生成的录音，营地和野外入夜换夜里的环境声，还没有录音的由代码合成）和 ACE-Step 生成的音乐（流式播放，放不了时由代码现场作曲）

## AI 美术

所有美术按 `avatar` 项目里的风格版（`concept/style/board.png`、`STYLE.md`：色板、材质、比例、出图规则、审图清单）统一生成，生成时把风格版的参考图一并喂给图像模型，保证同一套画风。批量流水线是 `avatar/pipeline/batch.mjs`，每组资源一个清单（`pipeline/sets/*.mjs`）。

### 角色和怪物

法师、圣殿骑士、营地里的四个 NPC（商人、佣兵、盗贼、守卫）和所有人形怪（`mon_*`）的模型和动作全部是 AI 生成的：设定图用图像模型画（正面 + 背面），然后用 [Meshy](https://www.meshy.ai) 的 API 转成带贴图的模型、自动绑骨、从动作库取待机 / 走 / 跑 / 攻击 / 格挡 / 施法 / 受击 / 死亡；法师普通攻击的挥杖是 Meshy 用文字描述生成的动作。生成流水线在隔壁的 `avatar` 项目里。NPC 文件名带 `npc_` 前缀，免得跟 KayKit 的同名角色撞车。

`tools/meshy-merge.mjs` 按 `tools/meshy-chars.mjs` 里每个角色的清单，把 Meshy 导出的几个文件合成一个 `models-src/ai/<角色>.glb`：统一动作名、去掉位移、把攻击和施法截到出手前后那一小段（出手点在攻击动作的 50%、施法动作的 55%），再跑 `tools/build-models.mjs` 输出到 `public/models/`：

```
node tools/meshy-merge.mjs sorceress paladin npc_vendor npc_mercenary npc_rogue npc_warden
node tools/build-models.mjs
```

主角的攻击、施法、受击和格挡在游戏里按暗黑 2 的帧数播放：动作片段整段缩放到原版档位算出的时长，结算落在原版的出手帧上（随职业和武器类别不同，在动作的 40% 到 60% 之间，见 `src/game/d2/frames.ts`），和截好的出手点大致对得上。怪物还是在动作的一半处结算。

怪物也用同一个合并工具：`mon(dir, clips)` 默认把动作原地化，并补上基础的走和跑。蝙蝠、幼龙、飞颅这几种不是人形的怪 Meshy 绑不了骨，是一整块静态模型，由顶点着色器做动作（`ModelSpec.motion`：扇翅、悬浮）。

蜘蛛用的是 [Tripo](https://www.tripo3d.ai)：同一张设定图生成模型，按八足骨架自动绑骨（62 根骨头，每条腿分 3 到 5 节），套它的八足走路预设，用 `@tripo3d/cli` 下载到 `models-src/tripo/`。`tools/tripo-merge.mjs` 把它转成游戏的朝向（Tripo 朝 +X）、改成非金属材质、走路提速 6 倍、用走路第一帧做一个静止的 `Idle`，写到 `models-src/ai/mon_spider.glb`。Tripo 的走路只有后两对腿在迈步，也没有攻击和死亡，所以 `src/render/legs.ts` 在动作之上用代码弯腿骨：走路时前两对腿按对角交替补上迈步；咬的时候前腿高举、毒牙张开，在动作一半处扑下去（正好是模拟结算伤害的时刻）；受击时腿一缩；死的时候腿收到身子底下、身子塌下去。

```
node tools/tripo-merge.mjs
node tools/build-models.mjs
```

Meshy 的骨骼没有手指，也没有挂武器的骨头，手里的东西由 `src/render/models.ts` 的 `hold` 摆放：
- 握点从手部网格量出来（绑定姿势下手部顶点的主轴给出手指方向和掌心朝向），落在掌心指根处；武器导入时就把原点放在握柄上（`ai-props.mjs` 的 `grip`），斧头、刀刃统一转到 +X 一侧。
- 朝向在待机第一帧按角色坐标摆好（剑朝前上方、刃口在前，十字弩水平朝前，盾面朝左前方），之后跟着小臂转，不跟手腕：Meshy 的动作是给空手做的，手腕会乱晃，握着武器时手腕应该是锁住的。
- 法杖平时保持竖直，只在普通攻击时随手腕挥动，否则比人还高的法杖会甩得很厉害。

### 道具、建筑、武器和贴图

`tools/ai-props.mjs` 按 `tools/ai-props-list.mjs` 把生成的模型导入 `models-src/ai-props/`。替换品沿用原模型包的名字（`d_*` 地牢、`h_*` 墓园、`x_*` 营地建筑和自然物、KayKit 武器和盾），并缩放、摆放到原模型的包围盒里，所以摆放它们的代码不用改；`build-models.mjs` 发现同名的 AI 版本就用它代替原模型。比例和原模型差得多的东西按某一边对齐（`fit: 'width' | 'height' | 'depth'`），画的角度不同的可以转（`yaw`、`pitch`），宝箱盖可以切下来单独开合（`split`）。

以前用代码拼的东西也换成了模型：营地的篝火、帐篷、传送点、墓穴入口和火盆（`p_*`），地牢里的骷髅堆、铁笼、旗帜、石笋、冰晶（`p_*`），双手剑、钉锤、巨槌、法杖、屠夫的切肉刀（`w_*`），地上的头盔、盔甲、手套、靴子、腰带、戒指、护身符、药剂和符文（`g_*`）；武器和盾掉在地上时就是手里拿的那个模型平放。火光、魔法光、宝石光仍由代码叠加。

地面和墙面贴图是生成后做成无缝的，`tools/ai-textures.mjs` 转成 `public/textures/*.webp`，渲染时按世界坐标铺。野外的草地、落叶和土路由 avatar 的 `pipeline/textures.mjs` 按风格版和已有地面画出来（每张 12 积分），再用 `pipeline/seamless.py` 做无缝；在 worktree 里转换时用 `AVATAR=<avatar 目录> node tools/ai-textures.mjs`。营地和野外的地面是一整块平面，`src/render/ground.ts` 按每格的比例混合四张贴图：比例图先用噪声推乱边缘，再按贴图本身的亮暗决定谁先露出来（草尖压在泥上、石子从土路里冒出来），看不出格子。大地图上每个区域各有一套四张贴图的「样子」（`src/render/arealooks.ts`），每格再记一份各区域样子的比例（`src/world/seams.ts`，交界两侧各约 4 格渐变），着色器用噪声把交界打成碎块；同一张贴图不管几个区域用都只采样一次。

```
node tools/ai-props.mjs [key ...]
node tools/ai-textures.mjs
node tools/build-models.mjs
```

### 物品图

背包、储物箱、魔盒、腰带、装备栏、商店和光标上的物品图（`public/icons/items/`，400 张，每张一份 2× 和一份 1×）由 `tools/ai-icons.mjs` 在 box 上画出、审过、导出，同时写出游戏读的清单 `src/data/itempics.ts`。原版的图只用来认清每件物品是什么，从不交给模型，导出前每张都和原版比过相似度（见 `public/icons/CREDITS.md`）。

游戏里按暗黑 2 的规则选图和上色（`src/items/picture.ts`，规则和 D2MOO 出处写在文件头）：

- 一张图对应一个 invfile，同一条底材线的普通、扩展、精英三档共用一张。
- 戒指、护符、护身符和珠宝在生成时掷出一种外观（`Item.gfx`）存进存档，读档后不变；之前的物品按 uid 定一种。
- 暗金先用自己的图，再用底材的 uniqueinvfile；套装用底材的 setinvfile；都没有就显示底材的图。
- 颜色照 ITEMS_GetColor：魔法和稀有物品取第一个带颜色的后缀，没有再取前缀；暗金和套装取各自的 invtransform；普通物品第一个孔里是宝石时取宝石的颜色。底材的 InvTrans 决定哪些色段跟着变，0 不变。

- 符文的编号画在石头上，孔和孔里的东西照旧画在图上面。

图在面板第一次要显示时才去取（`src/ui/itempics.ts`）。到之前格子里先显示代码画的图标，图解码好才换上，大小不变；没画的或取不到的物品一直用代码画的图标。屏幕一个 CSS 像素对一个设备像素时用 1×，其他用 2×。

## AI 声音

**音效与配音由 ElevenLabs 生成**（[elevenlabs.io](https://elevenlabs.io)）。用的是免费档：按它的条款不能商用，发布时要注明 elevenlabs.io；每个文件的提示词或台词、模型和音色见 `public/audio/CREDITS.md`。

**音乐由 ACE-Step 1.5 生成**（[github.com/ACE-Step/ACE-Step-1.5](https://github.com/ACE-Step/ACE-Step-1.5)，代码和权重都是 MIT 许可，生成的音频可以自由使用），在我们自己的 GPU 机器上跑，见下面「音乐」。

`tools/ai-audio.mjs` 按 `tools/audio/list.mjs` 的清单向 ElevenLabs 要声音：音效和环境声用文字生成音效（`eleven_text_to_sound_v3`，指定时长和贴合提示词的程度，环境声要可循环的），配音用文字转语音（从 `/v1/models` 里挑读中文最好的模型，目前是 `eleven_v4`；每个说话人在清单里选一个预置音色）。原始输出留在 `audio-src/`（不入库），再后期处理成 `public/audio/<id>.<n>.m4a`：

- 音效和配音转成单声道，切掉首尾的静音，两头淡入淡出；
- 响度按 BS.1770 归一：音效 -16 LUFS（短时）、配音 -18、环境声 -24（整段），峰值压在 -1 dBFS 以下，超出的限幅（音效最多 6 dB，环境声里偶尔爆一下的柴火最多 14 dB），限幅用满了还不够就宁可小声；
- 环境声把结尾交叉淡化进开头，做成无缝循环，前后各留 0.25 秒它自己的波形，记下循环点：浏览器解码时差几毫秒，接缝也还在同一段波形上；
- 编码成 AAC：单声道 64 kbps，立体声 96 kbps，音乐 128 kbps。

同时重写 `src/audio/files.ts`（游戏的录音清单）和 `public/audio/CREDITS.md`。清单里没有录音、或录音加载失败的声音由代码合成。

录音统一归一到同一个响度，放进游戏前还要对音量：清单里每条的 `gain` 把它调到它所替换的合成音在混音里的位置（合成的挥砍声很轻，因为每次攻击都会响；同样 -16 LUFS 的录音比它响 22 dB）。`tools/scenarios/sfx.mjs` 把游戏发布的每个录音和它替换的东西在 OfflineAudioContext 里走完整条链路（各自的音量、主音量、压缩器）渲染出来，在 Node 里用同一个 BS.1770 表对比：音效对合成音，比瞬时响度（400 ms 窗口，短促的声音按听到的算）；环境声对该区域的合成底噪，比淡入之后的整段响度。差 3 dB 以上就报错，并给出能对上的 `gain`。主角台词没有合成音可比，按游戏里说台词的音量渲染，和主角最响的提示音（升级、暗金掉落的合成音）比瞬时响度，差 4 dB 以上报错，并给出能对上的音量；其他没有任何代码会播的录音报错。

主角的台词写在 `tools/audio/voice-lines.md`：一张表，每行一个场合（背包满了、法力不够、用不了、升级、生命垂危、捡到暗金、进入野外或地下城……），圣殿骑士和法师各说各的话。清单直接读这张表，生成 `voice.<职业>.<键>`；场合的键登记在 `src/audio/sounds.ts` 的 `HERO_LINES`，测试会核对两边一致。改了哪句台词，下次带 `--budget` 运行只重新生成那一句。NPC 的配音之后按月再做。

游戏里由 `Game.say` 说台词（`sfx.play('voice.<职业>.<键>')`），文字提示照旧显示：背包满了捡不起来、法力不够、装备不上（别的职业的或放不进那一格、等级不够、力量敏捷不够各说各的）、金币不够、营地里开传送门、按了空的腰带格、升级、生命掉到三成以下（回到五成以上、过了 30 秒才会再说）、中毒、第一次捡起暗金套装或符文、走出营地、回到营地（在营地交界上来回走时不重复说）、每局第一次下到地下城、野外入夜、激活传送点、碰神龛、头目惊醒和被打倒。同一时间只说一句，说完停 1.2 秒才说下一句，同一句 8 秒内不重复；台词还没解码的话等解码好再说，晚过 0.8 秒就不说了。走进一个区域时，游戏把这里会听到的音效、相邻区域（交界的另一边、洞口和出口通往的地方）的环境声和走进那里要说的台词提前解码。

营地和野外的环境声分白天和夜里（`src/audio/sounds.ts` 里区域的 `amb` 和 `night`）：天色的黄昏和黎明过半时（`DUSK`、`DAWN`），`Sfx` 用六秒把一种交叉淡化成另一种；夜里那种还没有录音或加载失败时，白天的接着放。

```
node tools/ai-audio.mjs --dry                 # 要生成什么、估计花多少积分
node tools/ai-audio.mjs --budget 6000         # 生成，本月用量到 6000 积分之前停下
node tools/ai-audio.mjs                       # 只重做后期，不花积分
```

随时可以中断再跑，同一个请求只生成一次：`tools/audio/made.json`（入库）记着每个文件由什么请求（连同提示词或台词）、什么处理得来，换一个检出也不会重新花钱。改了提示词、台词、时长或音色的条目要带 `--budget` 才会重新生成；在那之前旧录音照常播放，CREDITS 里照旧署名，写的是生成它的那一版提示词。`public/audio/` 里的每个录音都在 CREDITS 里；清单不再要的文件、made.json 没有记录的文件，运行时会列出来，`--prune` 删掉。只改响度目标的只重做后期，只改 `gain` 的只重写 `files.ts`。

免费档每月 1 万积分，音效约每秒 10 积分，配音每个字 1 积分。订阅接口报的用量要晚几分钟才更新，所以工具同时按每次请求返回的 `character-cost` 自己记账，`--budget` 按两者中大的算；时长为 `auto` 的条目最长能到 30 秒，`--budget` 按 30 秒算，免得一条就超出几百积分。

### 音乐

每个声音环境一首，照原版的分法（levels 表的 SoundEnv，`src/audio/sounds.ts` 的 `ENVIRONS`）：营地 `music.town`、野外 `music.wild`（血沼荒原和凛寒原野接着放同一首）、洞穴 `music.dungeon`。也照原版的放法（sounds 表里 music_town_1、music_wilderness、music_caves 都是 Stream、Loop、Is2D）：`Stream` 用 `<audio>` 边下边放，立体声，不放到场景里，一首就循环，几首就轮流。现在的几首：

| id | 录音 | 听起来 |
| --- | --- | --- |
| `music.town` | 2 首轮流 | 尼龙弦古典吉他独奏，一首 D 小调、一首 E 小调 |
| `music.wild` | 1 首 | 暗色的管弦：低音弦乐持续音、大提琴、像合唱的长音垫 |
| `music.dungeon` | 1 首 | 超低音持续音、像合唱的长音垫，洞穴般的空间感 |

都是 ACE-Step 1.5 的 turbo 模型（`acestep-v15-turbo` 加 `acestep-5Hz-lm-1.7B` 语言模型）出的，从每个环境的几版里挑的：让语言模型听回每一版写描述，再看测出来的特征。4B 的 XL-sft 模型正在出更好的版本，之后会换。

音乐只在 GPU 机器上生成，**不在本机跑任何模型**（本机跑模型时差点卡死）。`tools/audio/acestep.py` 放到装了 ACE-Step 1.5 的机器上，在它的 uv 环境里跑；任务文件就是清单里的音乐条目（提示词、速度、调性、拍号、时长、模型、语言模型、采样设置，每一版一个种子），每一版写成 `<名字>.wav` 和一个同名的 `.json`，记着生成它的全部参数和生成时间。box 上经 ssh 跑的命令 PATH 里没有 `~/.local/bin`，所以 uv 要写全路径；DiT 或语言模型加载失败时脚本直接退出，不会生成一版记错了模型的录音：

```
node tools/ai-audio.mjs --jobs jobs.json      # 清单里要、但找不到原始录音的那几版，写成任务文件
ssh box 'mkdir -p ~/ace-jobs' && scp tools/audio/acestep.py jobs.json box:ace-jobs/
ssh box 'cd ~/ACE-Step-1.5 && CUDA_VISIBLE_DEVICES=0 ~/.local/bin/uv run python ~/ace-jobs/acestep.py ~/ace-jobs/jobs.json ~/ace-out/xl'
scp -rp 'box:ace-out/xl' audio-src/acestep/   # 放回本机（audio-src 不入库），-p 保留生成时间
node tools/ai-audio.mjs music.                # 后期处理，重写 files.ts 和 CREDITS
```

`tools/ai-audio.mjs` 处理音乐不碰 ElevenLabs，也不花积分：清单里每一版按它的种子和参数，到 `audio-src/acestep/` 下找记录完全相同（caption、速度、调性、拍号、时长、种子、模型、语言模型，以及采样的步数、guidance、shift）的那个 `.json`，用旁边的 `.wav`，不管文件叫什么、放在哪个子目录（链接进来的目录也算）。清单没写采样设置的按模型的默认值：turbo 8 步、guidance 1（即不用）、shift 3，其他模型 64 步、guidance 7、shift 3，和两个生成脚本一致；早先 `gen-reference.py` 写的 `.json` 没记采样设置，按这个默认值认。made.json 还记着原始录音的哈希，同名同参数的录音换了内容（比如在另一台机器上重新生成）也会重新处理。找不到的会列出来，说要到 GPU 机器上用 `acestep.py` 生成（`--dry` 也列），运行照常结束；旧的那版照常播放，CREDITS 里照旧署名。CREDITS 里的日期取 `.json` 里的生成时间，没有的话取文件的修改时间，所以从 GPU 机器拷回来要用 `scp -p`。后期处理：保持立体声，去直流，切掉模型留在结尾的 5 到 12 秒静音，开头淡入 50 ms、结尾淡出 3 秒，整段响度归一到 -18 LUFS，采样峰值限幅到 -1.5 dBFS，编码成 128 kbps 的 AAC；编码会在峰值上冲出一点（-1 dBFS 限幅的一首编码后真峰值到了 -0.9），所以编码后回读文件，量 4 倍过采样的真峰值（和 ebur128 的量法一样），超过 -1 dBFS 就把限幅再压低超出的量重新编码，made.json 记着成品的 `truePeak`。不记循环点（`Stream` 整个文件循环）；文件的元数据写的是 ACE-Step 和种子。

音量和录音一样用 `gain` 对：每首调到它替换的代码作曲在混音里的位置（经过音乐总线 `MUSIC_LEVEL` 之后约 -45 LUFS）。`tools/scenarios/sfx.mjs` 把每首的每一版整段，和放这首音乐的每个区域的代码作曲（淡入之后 90 秒），在 OfflineAudioContext 里走同一条链路渲染出来比整段响度，差 1.5 dB 以上就报错，并给出能对上的 `gain`。同时按 `MUSIC_LEVEL` 的本意核对它和别的声音的关系：整段响度要比它所在每个区域的环境声（白天、夜里；没有录音的洞穴是合成底噪）低至少 1 dB，比打斗声低至少 6 dB（打斗声取命中、格挡和怪物死亡这 8 种声音瞬时响度的中位数，约 -38 LUFS；代码作曲就在它下面 6 到 8 dB），最响的 3 秒也要比打斗声低至少 1.5 dB；不满足就报错，并给出满足的 `gain`。录音的起伏比代码作曲大：营地那两首吉他最响的 3 秒离打斗声只差 1.3 dB，所以 `gain` 从 0.13 降到 0.12，整段比代码作曲低 0.4 dB。

游戏里的放法由 `tools/scenarios/music.mjs` 走一遍核对（和玩家一样点一下才开始出声）：
- 营地两首轮流放，一首放到结尾接下一首，音量不再重新淡入。
- 走出营地进血沼荒原，野外那首在营地那首上交叉淡入，和环境声一起只换一次。在接缝上来回走，换的次数不超过环境声（两次切换至少隔 `SWITCH_HOLD` 2 秒）；回到上一个区域时，如果它的音乐还在淡出，就把那一首拉回来接着放（`Stream.revive`），不掐断，也不从头开始。
- 进凛寒原野接着放同一首；邪秽巢穴放洞穴那首，出来回到野外那首；传送点和死后复活回营地，都换成营地那首；重新载入页面后，从下一次点击开始放存档所在区域的那首。
- 每首都是两个复用的 `<audio>` 元素之一上的 `Stream`：请求是媒体类型（206 分段，`audio/mp4`），不会整首解码成 AudioBuffer。在主音量处量到的音乐和文件本身那一段乘上各级音量一致（差 0.0 dB）；在血沼荒原，命中声和死亡声最响的 400 ms 各比那一段音乐高约 7 到 8 dB（剧本要求两种各自至少 6 dB；普通怪物的死亡声原先比命中声小 1 dB，只高出 6.0 dB 上下，时过时不过，现在和命中声一样响，大怪的再响一档）。两个元素都被占着时再来一首，先收回正在淡出的那个，不收回正在放的。

`tools/scenarios/audio.mjs` 还把游戏自带的三首分别弄坏（文件不存在、不是音频、第二首不存在），每种都退回代码作曲，警告里写明是哪个文件。

换一版：改 `tools/audio/list.mjs` 里那一条的种子或参数，把那一版的 `.wav` 和 `.json` 放到 `audio-src/acestep/` 下，再跑一次 `node tools/ai-audio.mjs`，别的都不用动。换了之后跑一次 sfx 剧本核对音量（不对就按它给的 `gain` 改清单，再跑一次工具），再跑一次 music 剧本。

AAC 编码会在开头加一段预备的静音（macOS 的 `aac_at` 是 2112 帧，约 44 ms），文件里的 edit list 让解码器去掉它。Mac 上的 Chrome 和 WebKit 都照做；万一哪个浏览器留着它，环境声有循环点前后的余量兜着，单次音效由 `Sfx` 解码时量出开头的静音、播放时跳过，不会晚 44 ms 出声。iPhone 上的 Safari 还没量过，按计划要在真机上用 Web Inspector 测一次。

## 体积与性能

- `build-models.mjs` 按类别给每个模型定面数和贴图上限（主角 2 万面，NPC 9 千、怪物 7 千、建筑 6 千、普通道具 3 千、小物件 1.5 千面配 256 贴图）。简化时限制最大形变，所以细骨头的骷髅、巫妖会停在 9 千到 1.2 万面；输出用 meshopt 高压缩档。
- 调试用的模型（`?aihero` 的 AI 英雄、`?knight` 的骑士和 KayKit 动作库）不带参数时不加载。
- 画面主要耗在像素着色上：默认（渲染分辨率「自动」）像素比最高 1.5，连续两秒低于约 45 帧就往下降一档（最低 1:1）；点光源只给最近的几个火把和特效（「中」档 4 + 3 个）。这些都能在设置里调。
- 静态场景（墙、柱子、地砖、火把、装饰）按 16×16 格分块，只有镜头或投影的灯照得到的块才挂进场景；火把的火星和点光源也只看附近的块。道具按模型合批，每帧逐个裁剪：镜头看得到的画进画面，影子可能落进画面的才画进阴影图（`src/render/chunks.ts`）。
- 怪物、地上物品和物件的视图在主角 30 格内才建，走出 40 格才释放，中间来回走不会反复建。怪物的骨骼模型第一次要画时才建，释放后按外观收进池子，留给下一只长得一样的怪（`src/render/views.ts`）；看不见、影子也落不进画面的怪不放进场景、不播动画，再出现时把落下的时间补上。
- 模拟里每帧遍历怪物的循环（AI、互相推开、瞄准、光环、飞行物命中）只查主角附近的怪（`src/game/monstergrid.ts`），远处睡着的怪不花时间，和暗黑 2 里没有玩家的房间单位不运行一样。
- 物品图一共 4.3 MB，但只取打开的面板里要显示的那几张，换储物箱页时只取那一页的。`tools/scenarios/icons.mjs` 在手机尺寸下量过（844×390、3 倍像素、CPU 降速 4 倍、4G 网速、2× 图都没取过、暂停游戏只量界面）：放满 48 件物品的储物箱页，面板绘制 70 毫秒，和只用代码画图标时（79 毫秒）一样，是打开时唯一的长任务；680 毫秒后 35 张图全部换上，期间每帧的 p95 是 10.2 毫秒，和空闲时一样。调色和换图每段最长 3 毫秒，每帧最多做 6 毫秒；再打开时不用等任何图。
- 小地图和自动地图把新探索的格子画进一张底图，显示时只拷贝要看的那一块；寻路的缓冲区换图也不重新分配。
- 只有一盏灯投影：地下城是主角头顶那盏，营地是月光。在 M5 Pro 上阴影每帧多 0.5 到 2 毫秒，画面特效（泛光、调色、雾气、飘尘）多 1.2 到 2.2 毫秒，两样都开时一帧从 2 毫秒左右变成 4.5 到 6 毫秒；「低」档两样都关。

改渲染前后用 `node tools/bench.mjs` 对比（需要先 `npm run dev`）；加 `--tour` 时沿路线走完整一圈就停，前后两次走的路一样。

## 测试工具

需要先 `npm run dev`，然后：

```bash
node tools/play.mjs tools/bot.mjs --url "http://localhost:5174/?dev"
```

机器人从 `--start-area`（默认血沼荒原 `wild`）按「营地、血沼荒原、邪秽巢穴、凛寒原野」的顺序一路打到 `--to` 之后（默认凛寒原野 `coldplains`，最后一块区域打到一只不剩），区域按键名写：`camp`、`wild`、`denofevil`、`coldplains`，试炼场是 `floor3` 这样（`--start-area floor3 --to floor7`）。`--class sorceress` 换法师，`--level 20` 让角色从 20 级开始（点数照职业配好，再从一堆按这个等级随机的装备里穿上最好的），`--minutes` 是最多模拟多少分钟（游戏内时间，快进运行）。每个职业怎么加点、用什么技能打，写在 `tools/bot.mjs` 的 `BUILDS` 里，只从角色学会的技能里挑。

单个机器人受装备运气影响很大，调平衡时用批量版本，并行跑多轮后按层给出死亡中位数、耗时、角色属性和死因。它默认连 `http://localhost:5174/?dev`，那里没有服务器时会自己起一个、跑完关掉，不用先 `npm run dev`：

```bash
node tools/balance.mjs --runs 16 --to coldplains --dump wild,denofevil
```
