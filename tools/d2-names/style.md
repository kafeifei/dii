# 改名规范

我们在做一款致敬《暗黑破坏神 2》的浏览器游戏，系统和数值照原版，但原版的专有名词全部换成我们自己的名字。每条输入有：`id`（原版内部键）、`en`（英文原名）、`zh`（官方简体中文译名，可能为空）、`ctx`（上下文：底材、所属套装、怪物、区域等）。

## 目标
- **老玩家一眼认出**：玩过原版的人扫一眼新名字，不看底材、属性和说明，就能说出它是原版哪一件、哪一个、哪个地方。他靠原名里最显眼的那部分认：核心词（风之力的「风」和「力」）、意象（橡树之心的橡树）、族名的词根（沉沦魔的「沉沦」）、音译名的读音（迪卡德·凯恩）。这部分要留在新名里。
- **但不是原名**：只改不妨碍认出的部分：换一个同义或近义的字，换修饰词、说法或语序，加一两个字，把物件换一种叫法。改一个字就够，只要它不是硬性规则 1 里那几种。改够了就停，不要往远处推：老玩家对不上号的名字，和照抄的名字一样不合格。英文原名的另一种译法也可以用，只要和官方简中差得够。
- **官方名是锚**：每条名字都记着它对照的官方简中（`official`）和英文原名（`en`），这两列不要删。起名、审名都拿它们比：先找出老玩家靠哪个词认它，留下；再看改得够不够（硬性规则 1）、还认不认得出（硬性规则 2）。改一个已有的名字时也对照官方名，不对照我们上一版的名字，免得一轮轮越改越远。官方中文为空时，以英文原名为锚。
- 风格：暗黑、哥特、古朴、有分量。不用现代词、网络用语、口语和外来流行梗。

## 硬性规则
1. **不能太像官方名**。下面几种都算没改：
   - 和官方简中完全相同（繁体、异体字算同一个字）；
   - 只加、删、换了「的」「之」这类虚字，或者只动了间隔号、空格：风之力 → 风的力、风力；
   - 只换了一个同音字（只差声调的也算）或一个形近字：风之力 → 风之立，谜团 → 迷团；
   - 上面几种凑在一起：风之力 → 风的立；
   - 音译名每个字都只换成同音字，念出来和官方译名一样：恰西 → 洽茜。游戏有中文配音，念出来就是官方名。

   名字也不能就是别的行的官方名（「腐尸」是官方另一种怪 Decayed 的名字，不能拿来叫僵尸）。
2. **要一眼认出**。老玩家靠它认的那部分（核心词、意象、词根、音译的读音）要留下，或者换成一看就对得上的近义字。下面这些都算认不出：
   - 换成另一个意象：狼獾之心 → 战彘之魂，钢铁 → 千锻刃；
   - 只剩结构，原词全换掉：不朽之王 → 镌石之君；
   - 换成老玩家不熟的同义词：狼獾之心 → 貂熊之魄，刺毛鼠 → 箭猪；
   - 要绕一道典故才对得上：弓手的 → 穿杨者的。

   认得出的改法，比如：不朽之王 → 不朽之君，狼獾之心 → 狼獾之魂，刺毛鼠 → 针鬃鼠，血鸦 → 绯鸦，女伯爵 → 浴血女爵。审的时候遮住 `official` 和 `en`，只看新名字，能马上说出原名的才算。
3. 不能用其他知名游戏、影视、小说的专有名词或标志性名字，比如魔兽、黑暗之魂、指环王、漫威这类。留下原词、只改一个字的时候尤其要查：风之力 → 风怒，就撞上了魔兽世界的「风怒」。
4. 同一批里不能重名；不同类别之间（暗金、套装件、符文之语）也尽量不要撞名。也尽量别用原版另一行的名字或它的核心词，免得老玩家认成那一件：「疾风」是符文之语 Wind 的官方名，拿来给弓起名，老玩家先想到的是那个符文之语。
5. 原版的人名、地名、神魔名音译时，**必须用术语表 `glossary.json` 里的新译名**，保证全游戏统一。术语表里没有的音译名，自己起一个新音译：念起来要让老玩家听得出原名（迪卡德·凯恩 → 戴克尔·喀因，塔·拉夏 → 陀·剌沙），但用字不同，也不能念出来和官方一样（规则 1）；起好后加进术语表，并在 `note` 里写明。
6. 长度：暗金、符文之语、套装名一般 2–6 个汉字；套装部件照原版的「人名的物件」结构。区域、怪物、NPC、任务名按原版的长短来。

## 按类别：留什么，怎么改
- **暗金、符文之语**：老玩家最熟的一类，常常只记得名字里的一两个词。留下这个词，改其余的：风之力 → 长风之力，暴雪重炮 → 雪崩巨炮，战争召唤 → 战争号召。两个字的名字，换一个字（谜团 → 诡谜），或者整个留下、加一两个字（钢铁 → 百炼钢铁）。
- **魔法前缀**（ctx 为 magic prefix）：游戏里物品名按「后缀 + 前缀 + 底材」拼起来，比如「保护之」+「翼龙的」+「长剑」。原版前缀以「的」结尾的，新名也以「的」结尾；原版是光秃形容词的（比如「棱彩」「钴蓝」），新名也不带「的」。词缀只有两三个字，老玩家认的是其中的实字：留一个，换一个，比如「暴虐」→「凌虐」、「弓手的」→「射手的」。
- **魔法后缀**（ctx 为 magic suffix）：原版以「之」结尾，新名也必须以「之」结尾，比如「防护之」→「护佑之」、「巨鲸之」→「沧鲸之」。
- **稀有名词库**：稀有物品名 = 第一个词 + 第二个词，比如「野兽」+「撕咬」。第一个词库（rare name first word）是名词或意象；第二个词库（item-type noun）是物品类名词或动作名词。新词也要两两拼起来顺口。和词缀一样，两个字留一个：野兽 → 凶兽。随机暗金怪名字的三个词库同理（剥皮者· → 剜皮人·）。
- **套装**：套装名和它的所有部件在同一批里。人名部分全套统一，用术语表的译名；套装名留核心词（不朽之王 → 不朽之君）。部件名照原版「X 的 Y」结构，Y 换一种说法，但还是那样东西：塔·拉夏的裹尸布 → 陀·剌沙的殓布。
- **怪物**：怪物种类名（比如「沉沦魔」「僵尸」）。僵尸、骷髅这类通用名词也不能和官方一样（导入会报错），换一个字，但一看还是那种怪：僵尸 → 朽尸。带原版特色的造词（沉沦魔、羊头人、鬼魂巫师这类）留住词根，换另一半：刺毛鼠 → 针鬃鼠。超级暗金怪是人名或称号：人名按人名规则处理，称号留核心词（血鸦 → 绯鸦，女伯爵 → 浴血女爵）。
- **区域、任务、NPC、佣兵名**：区域照原版意境改，留下地貌或核心词（「鲜血荒地」→「血沼荒原」，「石块旷野」→「列石荒野」）；任务名留住那件事（遗忘之塔 → 尘封之塔，搜寻凯恩 → 解救喀因）；NPC 和佣兵名是人名，按术语表或新音译处理。
- **技能**：只收带专有名词意味的（见下文 `skills.json`），留住召唤的那样东西：狼獾之心 → 狼獾之魂。

## 输出
每条输出 `{ "id", "en", "official", "name", "note" }`：`official` 就是输入里的 `zh`，`name` 是新名字，`note` 可以为空。官方中文为空时，参考英文起名。

## 名字放在哪里
起好的名字按类别存在本目录的 `<类别>.json` 里，以原版内部键为键：`"键": {"name", "nameEn", "en", "official", "note"}`（`official`、`note` 为空时省略）。`nameEn` 是我们的英文名，规则见 `style-en.md`；音译的英文写法在 `glossary-en.json`（`newEn`），和 `glossary.json` 一一对应。这些文件就是名字的唯一来源，直接在里面改。

- `uniques.json`：暗金（UniqueItems 的 index）；`sets.json`：套装和套装部件（Sets / SetItems 的 index）；`runewords.json`：符文之语（Runes 的 Name，如 `Runeword1`）。
- `prefixes.json`、`suffixes.json`：魔法前缀、后缀（字串键，automagic 也用这两份）；`rare-prefixes.json`、`rare-suffixes.json`：稀有名的两个词库。
- `bases.json`：名字里带专有名词的底材和任务物品（物品代码）。其余底材、宝石沿用官方的通用名；符文不起名，一律叫「N 号符文」。
- `monsters.json`、`areas.json`、`npcs.json`、`quests.json`：怪物和超级暗金怪、区域、NPC、任务。怪物按 MonStats 的 NameStr 字串键，超级暗金怪按 SuperUniques 的 Name，区域按 Levels 的 Id，NPC 按 NameStr。NameStr 是 `dummy`、`Dummy`、`a trap` 的（鸡、老鼠、营地里的哨兵、箭矢机关这类）游戏里不显示名字，不用起。
- `monster-prefixes.json`、`monster-suffixes.json`、`monster-titles.json`：随机暗金怪名字的三个词库（UniquePrefix / UniqueSuffix / UniqueAppellation 的字串键）。中文照官方的拼法：称号 + 前缀 + 后缀，称号以「·」结尾放在最前，比如「刽子手·晦冥蚀触」。前缀两个字，后缀是名词或「X者」，称号是「X者·」或两三个字的绰号。
- `skills.json`：技能（Skills.txt 的 skill 列，如 `Valkyrie`）。火球术、冰封球这类通用叫法沿用官方译名，不用收；只收带专有名词意味的（召唤物、灵体之类的称谓，比如女武神、橡木智灵）。名字取自符文之语字串的技能（迷狂的变身）自动用 `runewords.json` 里的名字。怪物技能游戏里不显示名字，不用起。
- `mercenaries.json`：佣兵的人名（Hireling 的 NameFirst…NameLast 之间的字串键，如 `merc01`）和佣兵类型名（字串键，如 `RogueScout`）。技能树名（「火系法术」「防御光环」这类）是通用词，沿用官方叫法。

`bases.json` 里 D2CE 没有中文字串的通用名（抗性卷轴这类）标 `"generic": true`：只有中文名，英文沿用官方的。

`node tools/d2-import.mjs` 只收录中英文名都有的行，缺名字的列在 `report.md` 里；名字和本行的官方译名相同或只差「的」「之」、间隔号和空格，是别的行的官方名，或者含有术语表替换掉的官方音译时，导入直接报错，`node tools/d2-validate.mjs` 也会再查一遍。繁体异体、同音字、形近字、念出来像不像、认不认得出，程序看不出来，要人来审。
