# 改名规范

我们在做一款致敬《暗黑破坏神 2》的浏览器游戏，系统和数值照原版，但原版的专有名词全部换成我们自己的名字。每条输入有：`id`（原版内部键）、`en`（英文原名）、`zh`（官方简体中文译名，可能为空）、`ctx`（上下文：底材、所属套装、怪物、区域等）。

## 目标
- **相似但不同**：老玩家看到新名字，能大致认出对应的是原版哪一件、哪一个；但字面上必须和官方简中译名不同，也不能就是英文名的另一种直译。
- 做法：保留原名的核心意象（动物、元素、身份、器物、典故、情绪），换一种说法。可以用同义词、换结构、换修饰角度，或者把意象往前推一步（「风之力」→「逐风之怒」）。
- 风格：暗黑、哥特、古朴、有分量。不用现代词、网络用语、口语和外来流行梗。

## 硬性规则
1. 不能和官方简中译名完全相同。只改「的」「之」这类虚字，或者只换一个同音字，都不算改。
2. 不能用其他知名游戏、影视、小说的专有名词或标志性名字，比如魔兽、黑暗之魂、指环王、漫威这类。
3. 同一批里不能重名；不同类别之间（暗金、套装件、符文之语）也尽量不要撞名。
4. 原版的人名、地名、神魔名音译时，**必须用术语表 `glossary.json` 里的新译名**，保证全游戏统一。术语表里没有的音译名，自己起一个读音或气质相近、但用字不同的新音译，并在 `note` 里写明。
5. 长度：暗金、符文之语、套装名一般 2–6 个汉字；套装部件照原版的「人名的物件」结构。区域、怪物、NPC、任务名按原版的长短来。

## 按类别的额外规则
- **魔法前缀**（ctx 为 magic prefix）：游戏里物品名按「后缀 + 前缀 + 底材」拼起来，比如「保护之」+「翼龙的」+「长剑」。原版前缀以「的」结尾的，新名也以「的」结尾；原版是光秃形容词的（比如「棱彩」「钴蓝」），新名也不带「的」。
- **魔法后缀**（ctx 为 magic suffix）：原版以「之」结尾，新名也必须以「之」结尾，比如「防护之」→「护佑之」。
- **稀有名词库**：稀有物品名 = 第一个词 + 第二个词，比如「野兽」+「撕咬」。第一个词库（rare name first word）是名词或意象；第二个词库（item-type noun）是物品类名词或动作名词。新词也要两两拼起来顺口。
- **套装**：套装名和它的所有部件在同一批里。人名部分全套统一，部件名照原版「X 的 Y」结构，Y 换一种说法。
- **怪物**：怪物种类名（比如「沉沦魔」「僵尸」）。僵尸、骷髅这类通用名词可以保留；带原版特色的造词（沉沦魔、羊头人、鬼魂巫师这类）要改。超级暗金怪是人名或称号，按人名规则处理。
- **区域、任务、NPC、佣兵名**：区域照原版意境改（「鲜血荒地」→「血沼荒原」这种程度）；NPC 和佣兵名是人名，按术语表或新音译处理。

## 输出
每条输出 `{ "id", "en", "official", "name", "note" }`：`official` 就是输入里的 `zh`，`name` 是新名字，`note` 可以为空。官方中文为空时，参考英文起名。

## 名字放在哪里
起好的名字按类别存在本目录的 `<类别>.json` 里，以原版内部键为键：`"键": {"name", "en", "official", "note"}`（`official`、`note` 为空时省略）。这些文件就是名字的唯一来源，直接在里面改。

- `uniques.json`：暗金（UniqueItems 的 index）；`sets.json`：套装和套装部件（Sets / SetItems 的 index）；`runewords.json`：符文之语（Runes 的 Name，如 `Runeword1`）。
- `prefixes.json`、`suffixes.json`：魔法前缀、后缀（字串键，automagic 也用这两份）；`rare-prefixes.json`、`rare-suffixes.json`：稀有名的两个词库。
- `bases.json`：名字里带专有名词的底材和任务物品（物品代码）。其余底材、宝石沿用官方的通用名；符文不起名，一律叫「N 号符文」。
- `monsters.json`、`areas.json`、`npcs.json`、`quests.json`：怪物和超级暗金怪、区域、NPC、任务。怪物按 MonStats 的 NameStr 字串键，超级暗金怪按 SuperUniques 的 Name，区域按 Levels 的 Id，NPC 按 NameStr。NameStr 是 `dummy`、`Dummy`、`a trap` 的（鸡、老鼠、营地里的哨兵、箭矢机关这类）游戏里不显示名字，不用起。
- `monster-prefixes.json`、`monster-suffixes.json`、`monster-titles.json`：随机暗金怪名字的三个词库（UniquePrefix / UniqueSuffix / UniqueAppellation 的字串键）。中文照官方的拼法：称号 + 前缀 + 后缀，称号以「·」结尾放在最前，比如「刽子手·晦冥蚀触」。前缀两个字，后缀是名词或「X者」，称号是「X者·」或两三个字的绰号。
- `skills.json`：技能（Skills.txt 的 skill 列，如 `Valkyrie`）。火球术、冰封球这类通用叫法沿用官方译名，不用收；只收带专有名词意味的（召唤物、灵体之类的称谓，比如女武神、橡木智灵）。名字取自符文之语字串的技能（迷狂的变身）自动用 `runewords.json` 里的名字。怪物技能游戏里不显示名字，不用起。
- `mercenaries.json`：佣兵的人名（Hireling 的 NameFirst…NameLast 之间的字串键，如 `merc01`）和佣兵类型名（字串键，如 `RogueScout`）。技能树名（「火系法术」「防御光环」这类）是通用词，沿用官方叫法。

`node tools/d2-import.mjs` 只收录有名字的行，没名字的列在 `report.md` 里；名字和官方译名相同、或者含有术语表替换掉的官方音译时，导入直接报错。
