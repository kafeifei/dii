# 项目地图

这份文档用来盘清项目。改动牵涉多个模块、合并分支、或准备发布时，先对照这里，确认没有破坏下面列出的规则。代码变了，这份地图跟着改。

总体计划和进度见 `docs/PLAN.md`：系统照《暗黑破坏神 2：重制版》（术士资料片之前的版本）复刻，专有名词全部换成我们自己起的名字，地图重做整个第一幕。正在做的 M2a 的决定见 `docs/M2A.md`。

## 运行时结构

`src/main.ts` 建三样东西，每帧按固定步长（1/60 秒）推进：

- **Game**（`src/game/game.ts`）：模拟层，持有主角、当前地图、怪物、物件、共享储物箱、任务、难度。不碰 DOM，通过 `GameHooks` 通知界面（消息、开面板、死亡、换区、主角被别的窗口接管、存档状态等）。
- **Renderer**（`src/render/`）：Three.js 画面，只读 Game 的状态。
- **UI**（`src/ui/`）：DOM 界面，实现 `GameHooks`；标题页、暂停菜单、各个面板、HUD、触屏控制都在这里。

`?dev` 是测试模式：跳过标题页直接开测试角色，用单独的存档位（`dii-save-dev`），页面不可见时模拟也照跑。自动化测试都用它；你实际玩的地址不要带 `?dev`。

**模型按需加载**（`src/render/assets.ts`、`needs.ts`，2026-10-29）：
- 标题页只等 `needs.ts` 的 `CORE`：两个主角和武器包、掉落物包、营地和它的人（营地、墓园、草木三个包，四个 NPC），11 个文件约 8 MB。「新的冒险」「继续」能按以后，其余的在后台按顺序下（`assets.stream`）：大地图上营地以外的区域，再是地牢。`?gallery` 等全部模型。
- `Renderer.buildLevel` 先要这张地图用到的模型（`levelNeeds`）：主角所在区域的最先（`NOW`），其余的次之（`HERE`），再预取从这里能去的地方（`areaNeeds`，`NEXT`）。`NOW` 的没下完以前，别的一个都不开始。
- 建图前先挡住后台（`assets.hold`，在要模型之前）：这张地图的地面和墙面贴图先下，`NOW` 以外的下载等它们下完；正在下、还差一半以上的后台下载停下（`assets.makeWay`，不算一次失败），放开后从头下。`NOW` 的有要等的时也这样给它们让路。
- 还没到的模型照「模型缺失」那样先用替身：角色和怪物是代码画的骨架，道具不画，火把、装饰、柱子、房子、物件、地上的物品是代码画的样子。模型到了就换上，每样只换一次；换之前先把它的贴图一帧一张传上显卡，每帧换的时间不超过 4 毫秒。视野外的替身怪模型到了就直接扔掉，下次看见时用模型造。主角所在区域的模型 1.5 秒还没齐，就盖上「载入中…」并暂停世界（这时照样报心跳，见下文「一个角色只在一个窗口里玩」），齐了再揭开。
- 解析模型、造模板的活都分段，每帧一共 4 毫秒（「载入中…」盖着时 24 毫秒），所有正在来的文件共用：开始解析一个文件前先等到自己那份；文件里每张图（Blob、URL、fetch）各占一个任务（`slicePictures`）；造模板、算包围盒也分段。标题页和隐藏的页面没有帧可等，分段之间只让出一个任务（用消息，不用后台会被限到一秒一次的定时器）。地面和墙面贴图一帧只解码上传一张（`textures.ts` 的 `admitTile`）。
- 下载失败（或 15 秒没有数据）隔一会儿再试一次，还不行就放手：替身留着，不再让任何东西等它，之后在后台越隔越久地再试，下好了照样换上。没有任何文件带着的模型（`assets.serves` 为假）不等，照以前那样不画。
- 新代码凡是用 `assets.get` 造东西，都要放在 `assets.watch` 里造（它记下缺了哪些模型，替身才会被换掉），并在 `needs.ts` 里写明它要哪些模型；`tools/test/needs.test.mjs` 核对这两边对得上。

## 存档：存什么、什么时候存、谁能写

**存储位置**（都在浏览器本地，按网址区分；5174、Vercel、内部站点各是各的）

| 键 | 内容 |
| --- | --- |
| `dii-save-v1`、`dii-save-v1-1`…`-7` | 8 个角色位，每位一个角色（`SaveV4`，在 `src/game/save.ts`） |
| `dii-save-v1-backup-…` | 每次迁移前的备份：v4 以前的全留着，v4 的只留最早和最新两份 |
| `dii-shared` | 共享储物箱的 5 页，归玩家而不是角色 |
| `dii-tab:<存档键>` | 哪个窗口正在玩这个角色（见下文「一个角色只在一个窗口里玩」） |
| `dii-settings` | 设置 |
| sessionStorage `dii-in-game`、`dii-slot` | 本页正在玩哪个角色位。刷新本页时靠它直接接着玩 |

**`SaveV4` 存的东西**：
- 等级、经验、属性、技能和点数、装备、背包、个人储物箱、魔盒、腰带、光标上的物品、身上和储物箱的金币。
- 快捷键、开着的光环、所在区域和地图种子（刷新时用）、难度。
- 三个难度各自的传送点和任务标志。
- 尸体（一具，带物品）、佣兵（还没做，原样写回）、生命和法力。

存档里不认识的物品放到营地储物箱旁边，不会删掉。

**什么时候写**：
- 每 8 秒自动存。
- 进入新区域、点亮传送点、打败首领、换难度时存。
- 共享储物箱有变动时存。
- 关页面、页面切到后台、Esc 菜单「保存并返回标题」时存。返回标题时先关掉镇民的对话：正说着的话算听完，跟这个角色一起存下（`NpcPanel.quit`），不留在标题页下面，也不会算到接着玩的角色头上；任务日志按钮上的新消息也不带过去。存完档，屏幕上的提示消息也一并清掉（比如退出时算听完的领奖台词给出的「技能点 +1」，或者这次没存上的提示），不挂在标题页上，也不带进下一个角色的游戏；「未能保存」的标记照旧留着，直到下一次写成功。

**一个角色只在一个窗口里玩**（2026-10-28 修过一次严重 bug）：
- 正在玩的窗口每 3 秒刷新一次 `dii-tab:` 记录，表示自己还开着；「载入中…」盖着、世界暂停时也照样刷新（`main.ts`，盖着可能超过 10 秒）。
- 只有**刷新本页**会直接接着玩。复制标签页、从游戏里打开的新窗口一律回到标题页；正被别处玩着的角色，在标题页会标「正在另一个窗口里」。
- 在第二个窗口里选这个角色时，先等原窗口最后存一次、交接，再读档（`takeOver` → `waitHandOver`，最多等 3 秒）。
- 原窗口交接后立刻停下，整屏提示，只能回到标题，从此不再写存档。
- 写存档失败时（比如存储满了），屏幕上方一直显示「未能保存」，直到下一次写成功。

**修 bug 前的教训**：原来复制的标签页会直接进游戏并接管角色，原窗口照样能玩却不再存档，只在角落提示 10 秒。点亮的传送点、捡的东西就这样静默丢了。凡是「这里的操作不会被保存」的状态，都必须让游戏停下，不能只提示一句。

## 必须守住的规则

1. **存档不丢、不复制物品**。任何移动物品的改动（储物箱、魔盒、Ctrl+点击、交易、尸体、两个窗口），都要逐件清点，确认没有丢也没有多。
2. **玩着的东西一定存得下来**；存不下来时游戏要停下，或者一直提示，不能静默。
3. **旧存档能读**：v1–v4 的样本在 `tools/test/save.test.mjs`，迁移前先备份。比当前版本新的存档只读、不回写。
4. **规则照原版**：数值和公式来自 `src/data/d2x`（d2data 的资料片列）和 D2MOO，注释里写明出处。原版没有的数，要注明是近似。
5. **名字**：全部走改名表（`tools/d2-names/`），老玩家一眼认得出，但不能和官方译名一样。规则见 `tools/d2-names/style.md`。
6. **美术和声音不侵权**：原版图片只用来看清物品是什么，不喂给模型、不描、不进仓库；成品都要过相似度查重。
7. **模型只在 box 上跑**，不在 Mac 上跑。
8. **后台代理不用 `rm`**，也不以 `cd` 开头写组合命令（会弹审批框，卡住代理）。
9. **模型没到时不能有东西静默缺失**：用 `assets.watch` 造、在 `needs.ts` 写明要什么，替身才会在模型到了以后换掉；没有替身的（道具）也要在模型到了以后补上。

## 配音

- **主角**：台词在 `tools/audio/voice-lines.md`，每个场合每个职业四句，`Game.say` 说，`src/audio/sfx.ts` 的 `Lines` 管一次只说一句、同一句隔一会儿才再说、不连着用同一条录音。
- **镇民**（现在只有亚喀蕾）：台词在 `src/data/dialogue.ts`：任务上的话、闲谈，加上问候和告别各三句（`GREETINGS`，只有声音）。`spokenLines()` 列出要念的每一句，录音叫 `voice.<NPC>.<键>`（`src/audio/sounds.ts` 的 `npcLine`，如 `voice.akara.a1q1_remind_out`）。
  - `node tools/dialogue-review.mjs` 生成审阅页 `tools/d2-names/DIALOGUE-zh.md`，「配音」一栏写着每句的录音编号和长度；`tools/audio/list.mjs` 照这一页的中文生成录音。
  - 改了台词：重新生成审阅页，录音念的是旧词的那几条标「要重录」；`node tools/ai-audio.mjs --budget <积分>` 录好，再生成一次审阅页。审阅页落后于台词或录音时，`quests` 单元测试失败。
  - 音色：ElevenLabs 预置的 Sarah（验证过中文的女声里最成熟、温和的一个；Lily 已经给了法师），语速 0.92，模型和主角一样由工具挑（现在是 eleven_v4）。`node tools/ai-audio.mjs --voices` 列出全部预置音色和它们验证过的语言。
  - 念错的字（多音字）：在 `tools/audio/list.mjs` 的 `SAY_AS` 里给那句换一个只有正确读音的同音字，只给配音看，显示的还是原字（提醒里「血沼荒原」的「血」给配音写作「谑」，念成 xuè；原来念成 xuě，听着像「雪沼」）。她每条录音里的多音字都核对过：box 上的 Whisper 听写并定位每个字，再看那个音节的音高走向和元音的共振峰（Whisper 写出的字分不清声调，要看音高）。结果记在 `made.json` 各条的 `check`，审阅页「配音」一栏写着「读音查过」。
  - 播放（`src/ui/npc.ts`、`Sfx.speak`）：任务上的话和闲谈照原版 `sounds.txt`（Stop Inst 1、Solo 1）一出来就念，打断主角正在说的话，说完之前主角不插嘴。文字从一开始就按录音的长度滚（每条录音的长度写在 `files.ts` 的 `secs` 里，录音没到也知道）：录音 0.25 秒内解码好就从头念，文字跟它的时钟走；晚到的录音从文字已经走到的地方接上（淡入），只剩不到 0.5 秒（`JOIN_MIN`）的才不放。跳过、再点她、Esc、走开或关掉对话就停（0.06 秒淡出）。音量比主角的台词低一档（照原版 `sounds.txt`：NPC 210、主角 255，这是故意的），声音从她站的地方来。保存并返回标题时先关掉对话：正说着的那句算听完（原版要先按 Esc 跳过台词才进得了菜单，一样算听完），记在这个角色身上再存档（`NpcPanel.quit`）。任务这边只认本局给出的台词（`Quests.spoke`），上一局留下的一句不会算到下一个角色或换过的难度上。
  - 提前取：主角在营地里时，游戏先把她接下来可能说的话的文件取回来（`Game.fetchAhead` → `Sfx.prefetch`）：她一开口要说的那句（接任务前是开场白，该领奖时是领奖的话），问候，「交谈」会说的那句，告别；每说完一句、每回到营地按新的进度再取。只取压缩的文件（她全部台词不到 1 MB），说的时候再解码（30 秒的开场白解码约 15 毫秒），不占解码后声音的 32 MB 预算（30 秒的单声道解码后约 6 MB）。
  - 问候和告别：一趟拜访里第一次打开她的菜单时问候（她一开口就有任务上的话要说时不问候），第一次离开时告别（取消、Esc、走开，或关上她的交易；从菜单打开交易不算离开）；走开 8 米以上再回来算新的一趟。照原版问候的 Stop Inst 0、Solo 0，问候和告别跟主角的话同时出声，不打断主角，主角也可以接着说；她自己没说完的问候会让给她的告别。原版只有问候没有告别，告别是我们加的。

## 发布

- **Vercel**：在没有未提交改动的检出里运行 `vercel build --prod`，再运行 `vercel deploy --prebuilt --prod`，地址是 dii-abyss.vercel.app。工作树里要有 `.vercel/project.json`，没有就从主检出复制。
- **内部站点**：发布方法、地址和登录都不在仓库里，用本机的内部站点 skill 发布，记下它报的版本。
  - 平台限制：最多 5000 个文件、总共 50 MB。2026-10-28 我们是 1117 个文件、43.2 MB；道具打包后（2026-10-29）是 987 个文件、39.5 MB，资源压缩还在做。
- `dist/` 只带游戏显示得出来的模型：调试用的（`?aihero`、`?knight`，见 `src/render/dev-models.ts`）只在 `npm run dev` 里有，构建时 `vite.config.ts` 去掉；用不到的列在 `tools/build-models.mjs` 的 `UNUSED`，不构建（2026-10-28 去掉这 8 个后是 1109 个文件、39.6 MB）。道具合成 `public/models/packs/` 下的 7 个包，模型从 154 个文件减到 32 个（2026-10-29 是 987 个文件、39.5 MB）。
- **体积上限**：`npm run build` 在 `vite build` 之后跑 `tools/check-dist.mjs`，按顶层目录列出 `dist/` 的文件数和大小；超过 2000 个文件、总共 40 MB，或者有一个文件超过 25 MB，就说出超在哪（最大的几个目录，或那个文件）并让构建失败。`vercel build` 跑的也是 `npm run build`，两边发布都要过这一关。内部站点的上限是 5000 个文件、50 MB，单个文件 25 MB（Cloudflare 的限制）；我们留出余量，新加的大资源在还来得及压缩、打包时就会被发现。MB 都按 1024×1024 字节算。
  - 2026-10-29：物品图拼成图集后是 336 个文件、42.2 MB，`npm run build` 因此失败；模型那条线的第一步（调试模型不进 `dist/`、5 个用不到的不构建）合进来后算下来是 328 个、38.6 MB，能过。

- 单元测试偶尔会有一次失败：是 `nearby`（2026-10-29 单跑十几次出一回），报「the path buffers hold 0 tiles on a 328×160 map」，像是那一局随机开出的大地图上还没有怪寻过路、缓冲区没分配，和模型无关，还要修。`icons` 场景会测手机上的性能，机器忙时偶尔超时失败（2026-10-28 一次用了 47 秒，平时约 18 秒），重跑通过。`monsters` 场景机器忙时也会失败一次（「Bishibosh didn't raise his fallen」）：等必希鲍什复活随从按真实时间等 14 秒，游戏每帧却最多只走 0.1 秒（`src/main.ts:39`），帧率一低，游戏里过的时间就不够；重跑通过。
