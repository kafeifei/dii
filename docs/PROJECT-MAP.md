# 项目地图

这份文档用来盘清项目。改动牵涉多个模块、合并分支、或准备发布时，先对照这里，确认没有破坏下面列出的规则。代码变了，这份地图跟着改。

总体计划见 `~/.claude/plans/twinkling-painting-dewdrop.md`：系统照《暗黑破坏神 2：重制版》（术士资料片之前的版本）复刻，专有名词全部换成我们自己起的名字，地图重做整个第一幕。

## 运行时结构

`src/main.ts` 建三样东西，每帧按固定步长（1/60 秒）推进：

- **Game**（`src/game/game.ts`）：模拟层，持有主角、当前地图、怪物、物件、共享储物箱、任务、难度。不碰 DOM，通过 `GameHooks` 通知界面（消息、开面板、死亡、换区、主角被别的窗口接管、存档状态等）。
- **Renderer**（`src/render/`）：Three.js 画面，只读 Game 的状态。
- **UI**（`src/ui/`）：DOM 界面，实现 `GameHooks`；标题页、暂停菜单、各个面板、HUD、触屏控制都在这里。

`?dev` 是测试模式：跳过标题页直接开测试角色，用单独的存档位（`dii-save-dev`），页面不可见时模拟也照跑。自动化测试都用它；你实际玩的地址不要带 `?dev`。

## 存档：存什么、什么时候存、谁能写

**存储位置**（都在浏览器本地，按网址区分；5174、Vercel、内部站点各是各的）

| 键 | 内容 |
| --- | --- |
| `dii-save-v1`、`dii-save-v1-1`…`-7` | 8 个角色位，每位一个角色（`SaveV4`，在 `src/game/save.ts`） |
| `dii-save-v1-backup-…` | 每次迁移前的备份：v4 以前的全留着，v4 的只留最早和最新两份 |
| `dii-shared` | 共享储物箱的 5 页，归玩家而不是角色 |
| `dii-tab:<存档键>` | 哪个窗口正在玩这个角色（见下文「一个角色只在一个窗口里玩」） |
| `dii-settings` | 设置 |
| sessionStorage `dii-in-game`、`dii-slot` | 本页正在玩哪个角色位。刷新本页时靠它直接接着玩 |

**`SaveV4` 存的东西**：
- 等级、经验、属性、技能和点数、装备、背包、个人储物箱、魔盒、腰带、光标上的物品、身上和储物箱的金币。
- 快捷键、开着的光环、所在区域和地图种子（刷新时用）、难度。
- 三个难度各自的传送点和任务标志。
- 尸体（一具，带物品）、佣兵（还没做，原样写回）、生命和法力。

存档里不认识的物品放到营地储物箱旁边，不会删掉。

**什么时候写**：
- 每 8 秒自动存。
- 进入新区域、点亮传送点、打败首领、换难度时存。
- 共享储物箱有变动时存。
- 关页面、页面切到后台、Esc 菜单「保存并返回标题」时存。

**一个角色只在一个窗口里玩**（2026-10-28 修过一次严重 bug）：
- 正在玩的窗口每 3 秒刷新一次 `dii-tab:` 记录，表示自己还开着。
- 只有**刷新本页**会直接接着玩。复制标签页、从游戏里打开的新窗口一律回到标题页；正被别处玩着的角色，在标题页会标「正在另一个窗口里」。
- 在第二个窗口里选这个角色时，先等原窗口最后存一次、交接，再读档（`takeOver` → `waitHandOver`，最多等 3 秒）。
- 原窗口交接后立刻停下，整屏提示，只能回到标题，从此不再写存档。
- 写存档失败时（比如存储满了），屏幕上方一直显示「未能保存」，直到下一次写成功。

**修 bug 前的教训**：原来复制的标签页会直接进游戏并接管角色，原窗口照样能玩却不再存档，只在角落提示 10 秒。点亮的传送点、捡的东西就这样静默丢了。凡是「这里的操作不会被保存」的状态，都必须让游戏停下，不能只提示一句。

## 必须守住的规则

1. **存档不丢、不复制物品**。任何移动物品的改动（储物箱、魔盒、Ctrl+点击、交易、尸体、两个窗口），都要逐件清点，确认没有丢也没有多。
2. **玩着的东西一定存得下来**；存不下来时游戏要停下，或者一直提示，不能静默。
3. **旧存档能读**：v1–v4 的样本在 `tools/test/save.test.mjs`，迁移前先备份。比当前版本新的存档只读、不回写。
4. **规则照原版**：数值和公式来自 `src/data/d2x`（d2data 的资料片列）和 D2MOO，注释里写明出处。原版没有的数，要注明是近似。
5. **名字**：全部走改名表（`tools/d2-names/`），老玩家一眼认得出，但不能和官方译名一样。规则见 `tools/d2-names/style.md`。
6. **美术和声音不侵权**：原版图片只用来看清物品是什么，不喂给模型、不描、不进仓库；成品都要过相似度查重。
7. **模型只在 box 上跑**，不在 Mac 上跑。
8. **后台代理不用 `rm`**，也不以 `cd` 开头写组合命令（会弹审批框，卡住代理）。

## 发布

- **Vercel**：在没有未提交改动的检出里运行 `vercel build --prod`，再运行 `vercel deploy --prebuilt --prod`，地址是 dii-abyss.vercel.app。工作树里要有 `.vercel/project.json`，没有就从主检出复制。
- **内部站点**：发布方法、地址和登录都不在仓库里，用本机的内部站点 skill 发布，记下它报的版本。
  - 平台限制：最多 5000 个文件、总共 50 MB。2026-10-28 我们是 1117 个文件、43.2 MB，资源压缩要先做。
- `dist/` 只带游戏显示得出来的模型：调试用的（`?aihero`、`?knight`，见 `src/render/dev-models.ts`）只在 `npm run dev` 里有，构建时 `vite.config.ts` 去掉；用不到的列在 `tools/build-models.mjs` 的 `UNUSED`，不构建（2026-10-28 去掉这 8 个后是 1109 个文件、39.6 MB）。

## 并行开发怎么做

- 大块工作各开一个工作树和分支（`.claude/worktrees/<名>`），测试用各自的端口（5181–5190）。5174 是你在用的，不碰。
- **合并前我自己核对**：
  - 两边改动的交叉点，尤其是存档、物品移动、界面状态；
  - 新加的「保护」或「限制」会不会让玩家的操作静默失效；
  - 跑上面的发布前清单。
- 每次合并或发布后，更新这份地图。
